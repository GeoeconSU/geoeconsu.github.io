# Changes for the RAO Dashboard (2026-11-02)

This document records all changes made to `rao.html` (the RAO Observatory dashboard) during the 2026-11-02 work session: a round of UI/UX fixes and a correctness bug fix across the Overview, Analysis, Compare, and Rankings tabs, plus a first rollout of the info-tooltip ("?") system.

---

## 1. Overview tab

### Top 10 / Bottom 10 countries bar — Fixed
- **Problem:** `.gl-rank-bar` was `flex:1`, so its rendered width depended on how much space its sibling content (the live news-delta badge, lock icon, etc.) left over — meaning the same RAO score could render a visibly different bar length depending on what else was in the row, and the bar appeared to "jump" whenever the live lens toggled a delta badge on/off.
- **Fix:** `.gl-rank-bar` is now a fixed width (90px desktop, 55px mobile) instead of flexing, so its length is always a consistent percentage of the same base.

---

## 2. Analysis tab

### Country / Year selector shape mismatch — Fixed
- `#analysis-year-select` had different padding (`10px 12px` vs `10px 20px`), background (`--card-bg` vs `--w04`), and border-radius (`1px` vs `0`) than the country search box next to it.
- Unified both to the search box's treatment so the two controls read as the same family.

### 4-Pillar summary strip — label misalignment and mobile layout — Fixed
- **Desktop:** "C · Absorptive Capacity" is longer than the other 3 pillar labels and wraps to 2 lines at narrower widths, while the others stay on 1 line — this pushed that pillar's value/bar down relative to the other 3. Fixed by reserving a consistent `min-height` on the label row across all 4 cells, so the row stays aligned whether a label wraps or not.
- **Mobile:** the strip used to keep the same 4-column grid, so long labels wrapping made the section very tall with a lot of dead space. Rewired to a single-column, one-row-per-pillar layout: label on the left, a short horizontal bar, and the score beside it — per the agreed design.

### 4-Pillar Profile row — negative space — Fixed
- The row holding the 4-Pillar radar (left) and the stacked Score Decomposition + Take-off Detection Module cards (right) used `align-items:stretch`, forcing the shorter column to stretch to match the taller one — leaving a large blank void inside whichever card didn't need that much height. Changed to `align-items:start` so each column sizes to its own content.

### Chart pixelation — investigated, no code change
- Confirmed `switchTab()` already calls `chart.resize()` on every chart instance via `requestAnimationFrame` whenever a tab is activated, and no chart overrides `devicePixelRatio` (Chart.js already defaults to `window.devicePixelRatio`). No rendering bug found — what was seen is most likely a devtools zoom/emulation artifact, not an app issue.

### Peer Comparison — redesigned
- Replaced the old 4-column table (`min-width:520px`, forced horizontal scroll below that width) with a staggered 2x2 "card cluster" per pillar: Country and Global on the top row, Reg Avg and Top 10 on a second row offset down by half a box-height so it reads as a loosely fanned stack rather than a flat grid. The pillar name sits to the left, vertically centered against the cluster.
- Diff-vs-country is now conveyed by coloring the value itself (green/red against the gold "Country" box) instead of a separate line, keeping each box to 2 lines.
- No horizontal scroll at any width tested, including 390px mobile (stacks to one cluster per row).
- Also fixed: this function was using the same legacy fake-pillar calculation as the Compare tab bugs below (see §3) — it now reads the real `pillar_*` fields.

## 3. Compare tab

### Pillar Winners Scorecard — tie/scale bug — Fixed
- **The bug:** `renderPillarScorecard()` didn't use the real precomputed `pillar_opportunity` / `pillar_stability` / `pillar_absorptive_capacity` / `pillar_trajectory` fields at all. It recomputed its own "pillars" by averaging 2–3 unrelated raw `norm_*` variables each (a leftover from an old 6-pillar breakdown), and separately inverted only the "Fragility" entry via `10 - x` assuming a 0–10 scale. Reported symptom: Sri Lanka vs. Turkey showed a tie on every pillar despite real Trajectory scores of 0.35 vs. 0.83 — the fake 3-variable "Trajectory" average happened to land close for both countries, which the real pipeline-computed field does not.
- **The fix:** `renderPillarScorecard()`, `showPillarVariablesBreakdown()` (the click-to-drill-down modal), and `renderEnhancedPillarTable()` ("Enhanced Pillar Comparison") now all read the real 4 pillar fields directly (0–1 scale, consistent across all 4 — no more "Fragility out of 10"). The tie threshold dropped from `0.5` (calibrated for the old ad-hoc scale) to `0.02` (2% of the real 0–1 scale). The drill-down breakdown now pulls its variable list from `EXP_PILLAR_MAP` (the same canonical pillar→variable grouping used in the Analytics tab's variable manager) instead of the old 3-variable lists, so it shows more and more accurate underlying variables per pillar.
- **Known remaining scope:** the same legacy `OPPORTUNITY_PILLARS` / `STABILITY_PILLARS` / `calculatePillarScore()` pattern is still used in ~10 other places (Expanded Differential Analysis, Gap Analysis, Archetype Peer comparisons elsewhere, and several Analytics-tab functions — correlation heatmap, pillar correlation tracking, etc.). These were **not** touched this round — only the two Compare-tab components the bug was reported against, plus Peer Comparison (§2) since it was already being rewritten. Worth a dedicated follow-up pass if the same tie/scale issue shows up elsewhere.

### All Variables Comparison table — header alignment, diff placement, 3-country support — Fixed/Added
- **Header alignment bug:** the header row's cells were plain unstyled `<div>`s (default left-aligned) while the data rows below used `.variable-value { text-align: center }` — so header labels never lined up with the centered values beneath them. Fixed by giving header cells the same `variable-name` / `variable-value` / `variable-diff` classes as the data rows.
- **Difference column moved to the middle:** column order is now Variable Name → Country 1 → **Diff** → Country 2 (previously Diff was last).
- **3-country support added:** selecting a 3rd country now renders Variable Name → C1 → Diff(1v2) → C2 → Diff(2v3) → C3, using a smaller `.vars-3` grid variant. The leading value per variable is highlighted in gold (replacing the old red/green-per-country convention, which didn't generalize past 2 countries).
- **Mobile:** both the 2- and 3-country layouts now stack as "variable name on its own line, then all the values/diffs on a wrapping second line," with `overflow-wrap: anywhere` so long country names (e.g. "Bangladesh") wrap inside their own cell instead of being clipped. No horizontal scroll at 390px in either mode.

## 4. Rankings tab

### Filter panel — moved to the right (laptop view only)
- The filter `<aside>` already had independent scroll (`position:sticky` + its own `overflow-y:auto`) and an existing show/hide collapse toggle (`OBS.toggleFilters()`) — neither needed to be built. Only the position changed: swapped via explicit `grid-column`/`grid-template-columns` overrides (not just visual `order`, which would have also swapped which column got the narrow vs. wide track) at `min-width:1001px`, so results stay wide and left, filters stay narrow and now sit on the right. Mobile/tablet (≤1000px) layout is unchanged.

### Regional breakdown — now fits on one line
- Tightened `.regional-breakdown-chart`/`.region-pie-segment` (smaller font, smaller color swatch, tighter gaps, `white-space:nowrap` + `overflow-wrap` per segment) so all 5 region entries fit on a single row instead of wrapping or crowding.

### Main table — fits without horizontal scroll at laptop widths
- Reduced `th`/`td` padding and found the actual overflow driver: the Regime column's badge rendered the full `"SL · Stable / Low"` label at `white-space:nowrap`, making it by far the single widest column (197px vs. ~50–125px for everything else). Added a `compact` mode to `regimeBadge()` — the Rankings table now shows just the 2-letter code, with the full label retained as a hover tooltip. Table now fits exactly at 1366px and 1440px with no horizontal scroll (was ~200–280px over before).
- Sticky header (`position:sticky`) was already in place and unaffected by any of this.

## Round 2 (same day) — follow-up fixes after live review

A second pass fixing issues found after reviewing Round 1's output live, plus new requests.

### Overview — top/bottom 10 bars, root cause actually fixed
Round 1's fix (giving `.gl-rank-bar` a fixed width) was necessary but not sufficient: `.rank-country` was still `flex:1`, so it absorbed whatever space the variable-width trailing content (live-delta badge, present on some rows only) left over — shifting where the *bar itself started*, not just its width. Fixed by giving `.rank-country` a fixed width (150px desktop / 130px in the `#obs-league` glass context) with ellipsis truncation + a `title` tooltip for long names. Verified: every bar in both lists now starts at the exact same x-position regardless of country name length or badge presence.

### Analysis tab — selector box mismatch, actually fixed
Round 1's inline-style fix was silently overridden by a global `!important` rule (`.observatory select{background-color:#233049!important}`) and a height mismatch caused by `.search-box`'s own padding wrapping an input that *also* carries a shared `min-height:36px` rule (36+20px padding = 58px), while the bare `<select>` only gets the 36px applied to itself border-box (padding eats into it, not added on top) — same declared sizes, different rendered heights. Fixed by forcing both to an explicit `height:42px` and overriding the select's background with higher specificity (`#analysis-year-select` beats `.observatory select` even under matching `!important`).

### Analysis tab — 4-Pillar Profile / Score Decomposition now equal height, TDM moved out
- Changed `align-items:start` back to `align-items:stretch` so the radar and Score Decomposition cards are always the same height (radar drives it via its own `aspectRatio:1`/width-based sizing).
- Score Decomposition's waterfall bar chart (`.gl-decomp-plot`) now has `flex:1` instead of a fixed `240px` height, so it grows to fill whatever extra height stretching gives it — turning the old "negative space" into a nicer, larger chart instead of blank padding.
- Take-off Detection Module moved out of the split row entirely into its own full-width card below it, with its 4 gauges now in one horizontal row (`grid-template-columns:repeat(4,1fr)`, circles reduced from 118px to 96px) instead of a 2×2 grid. Mobile keeps the 2×2 fallback.

### Peer Comparison — redesigned again, per your ASCII mockup
Replaced the staggered/overlapping card design from Round 1 (which you found was overlapping) with a flush, borderless 2×2 grid: Country + Global on top, a thin divider, Reg Avg + Top 10 below, pillar name to the left — matching your sketch exactly. No boxes, no z-index stacking, alignment alone carries the structure.

### Compare tab — score breakdown alignment + 3-country row
- `.waterfall-title` (the big serif country name header on each "Score Calculation Breakdown" card) now reserves 2-line height via `min-height`, so a wrapping name like "Czech Republic" no longer pushes that card's content down relative to the others.
- The breakdown cards' grid changed from `repeat(auto-fit, minmax(280px, 1fr))` (which wrapped a 3rd country to its own row once the row got too narrow) to `repeat(${countries.length}, 1fr)`, so exactly 3 selected countries always render in one row.

### Rankings tab — quick stats, image position, and the sticky-header root cause
- Quick stats banner (Countries Shown / Average Score / Score Range / With Live Signals) changed from a 2×2 grid to one row of 4.
- The page-heading decorative image nudged left (`margin-right:276px`, desktop only) so it sits above the results column rather than flush against the page's outer edge, reading more as a pair with the filter panel below it. This one's an approximation of what you sketched — easy to nudge further if it's not quite right.
- **Root-caused why the sticky table header and the filter panel's "independent scroll" never actually worked**: `.section-container.glow-section` has `overflow:hidden` (originally to clip a decorative glow effect that this theme already disables via `display:none` — so the clipping was serving no purpose here), which sits between both the sticky `<th>` and the sticky filter `<aside>` and the real scrolling ancestor (`<body>`). Per the CSS spec, any non-`visible` overflow on an ancestor becomes the containing block for `position:sticky`, so neither could ever stick against the real page scroll. Fixed by adding `overflow:visible` to that one container (there's already an identical precedent for this exact fix on the Analysis tab).
- That alone fixed the filter panel's independent sticky scroll, but the table header needed one more fix: `.rankings-table` itself had `overflow:auto` with an unconstrained `height:auto` — meaning it technically counted as a "scroll container" (breaking sticky resolution past it) but never actually scrolled, so its sticky header had nothing to stick against. (A same-element `overflow-x:auto; overflow-y:visible` split doesn't work around this — per spec, pairing `visible` with a non-`visible` value on the other axis silently computes the visible one as `auto` too.) Fixed by giving the table a real bounded height (`max-height:70vh`) with `overflow:auto`, so it now has genuine internal scroll — which is also exactly what "frozen header, like Excel" requires, and incidentally gives the table its own independent scroll separate from the rest of the page, same as you asked for the filter panel. No "separate site" architecture needed — this was achievable entirely with CSS on the existing single page.

Full Playwright regression suite (24 tests) re-run clean after each major change, no regressions.
